The problem

Four agents running. Which one needs you?

Coding agents are great at working in parallel. Keeping track of them is the hard part.

  • WorkingRefactoring the payment serviceClaude Code · terminal 1
  • DoneWaiting for your next instructionCodex · terminal 2
  • Needs approvalWants to run dotnet ef database updateClaude Code · terminal 3
  • WorkingFixing the orders page on another branchGemini CLI · terminal 4

Without Nexora

Each agent lives in its own terminal or window. You only find out that one finished, or stopped to ask for permission, by clicking through all of them. An unanswered approval quietly blocks the whole task.

With Nexora

Every session lands on one live board, sorted by what needs you. Approve, deny or reply right on the card, get a notification when a session is waiting, and jump into the conversation only when you need to.

Why "ADE"? An IDE is built around your editor. An Agent Development Environment is built around your agents: their sessions, approvals, branches and tools. Nexora doesn't replace your agent; it's the place where you run and supervise it.

How it works

Three steps, no new accounts

  1. 1

    Connect your agents

    Nexora finds the coding agents installed on your computer. Each one signs in with its own account and plan, exactly as it does in the terminal.

  2. 2

    Monitor all your sessions

    Every conversation becomes a card: needs you, working, done or idle. Each card shows the project, the branch, its pull request and what changed.

  3. 3

    Take control when needed

    Allow, deny or answer the agent from the card or the conversation. Requests from subagents show which subagent asked.

What sets it apart

See every agent. Answer from one place.

Live board and approvals

Every session is a card that moves between needs you, working, done and idle. When an agent asks for permission, the request jumps to the top of the board. Approve it there and the agent keeps going, without opening its window.

  • Approvals from every session gathered in one place
  • Answer once for all sessions when the same request repeats
  • A desktop notification when a session is waiting

Agent orchestration

Give a big task to an orchestrator agent. It starts other agents through Nexora's own MCP tools, can put each one on its own branch and worktree, waits for them and answers their approvals. You follow the whole tree on a canvas and can step in at any point.

  • Agents created by the orchestrator are normal sessions on your board
  • Each one can run on a different model and effort
  • Its MCP tools are covered by end-to-end tests

Worktrees for parallel work

A new task gets its own branch and worktree off the project's base, so agents work in parallel without stepping on each other. Local config files come along and each worktree gets its own port.

Shared MCP hub

The MCP servers in your project's .mcp.json start once and serve every session, instead of one copy per conversation. They start on first use and stop when idle.

Trust and privacy

Your agents, your accounts, your code

Open source

MIT licensed. The whole app is on GitHub: read it, build it yourself, report issues or contribute.

What Nexora never touches

Your agents' logins. Each agent signs in on its own, and Nexora only checks that a login exists without reading it. You pay nothing beyond your agent's plan.

What Nexora stores

Only what you choose to give it: secrets an agent asks for through a protected form, cloud provider API keys and, for cloud machines, a claude setup-token. They are encrypted with Windows DPAPI or the macOS Keychain on your computer and never go into the chat.

Your code stays with you

Nexora has no AI of its own, doesn't upload your code and collects no telemetry. A test in the code fails on any analytics library, any read of the agents' logins or any new internet address. It goes online to check for updates, talk to GitHub and reach cloud machines you connect. Dashboard news and the weekly performance summary are optional and off by default. See everything that leaves your computer.

Not code-signed yet

Windows SmartScreen and macOS show a warning on first launch. It takes two clicks to open: see Windows or Mac.

What you need

At least one agent CLI signed in, Git, and Node.js if your projects use MCP servers.

FAQ

Frequently asked questions

What exactly does Nexora do?

It's a desktop app for working with several coding agent sessions at once. Your conversations sit on a live board that shows which ones need you, and you can answer approvals, review changes, manage branches and worktrees, bring in GitHub issues and hand big tasks to an orchestrator, all without switching windows.

What is an Agent Development Environment (ADE)?

An IDE is organized around files and an editor. An ADE is organized around agents: their sessions, the approvals they need, the branches they work on and the tools they share. Nexora still has an editor, diffs and a terminal, but the agents come first.

Who runs the commands: Nexora or the agent?

The agent you already use, such as Claude Code or Codex. It reads your code, edits files and runs builds and tests on your account and plan. Nexora has no AI of its own: it organizes the sessions and passes the agent's permission requests to you, according to the mode you pick. Nexora only runs what you ask it to, like creating a worktree or starting your project with Run.

Is it really free? Is it open source?

Yes to both. Nexora is free and MIT licensed, with the code on GitHub. The only thing you pay for is your agent's plan, as you do today.

Which agents work, and how well?

Claude Code and Codex have native integrations and the most features. Antigravity, GitHub Copilot, Cursor, OpenCode, Kiro, Qwen Code, Grok, goose and Gemini CLI work through the Agent Client Protocol and are in beta: features depend on what each agent reports. The compatibility table has the details.

Does my code leave my computer?

Not through Nexora, unless you turn on cloud machines for a project, which are off by default. The agent talks to its own provider, as it does in the terminal. Nexora goes online only to check for updates, talk to GitHub and reach the cloud machines you connect, and it doesn't collect usage data. An optional weekly performance summary, off by default, sends only resource numbers such as memory and CPU.

Does Nexora see my password or token?

Not your agents' logins: each agent signs in on its own, and Nexora only checks that a login exists. Nexora stores only credentials you paste into it yourself: a secret an agent asks for through the protected form, a cloud provider's API key and, if you use cloud machines, a claude setup-token token. All of them are encrypted in the system vault on your computer.

Windows says "Windows protected your PC". Is it safe?

The warning appears because the installer isn't digitally signed yet, and SmartScreen is wary of programs it hasn't seen before. Click More info, then Run anyway. If your browser blocks the download, open the downloads list, choose Keep and confirm. The source code is public if you'd rather build it yourself.

My Mac says Apple couldn't verify Nexora. How do I open it?

The app doesn't have Apple's paid signature yet. Drag Nexora into Applications and try to open it once; dismiss the message without moving it to the Trash. Then open System Settings › Privacy & Security, click Open Anyway next to the Nexora message and confirm. On macOS 12 to 14 you can also Control-click Nexora, choose Open and confirm.

My antivirus blocked it. Now what?

Use the portable version: it runs on the .NET runtime installed on Windows, which corporate antivirus software usually allows.

Is the app in English?

Yes. The app is in English and Brazilian Portuguese and follows your system language. You can switch it in Settings. The agent replies in whatever language you write in.

How do I update?

When a new version is out, an Update button appears at the top of the window. One click downloads it, closes Nexora, installs the update and opens it again.
