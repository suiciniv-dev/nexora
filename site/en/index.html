New in 0.8

Agents leave your PC. Nexora enters your terminal.

The 0.8 release moves the heavy work to a cloud machine and lets you drive Nexora from scripts, without taking away anything that already worked.

Cloud machines

Connect your own machine over SSH or create one with an API key. Each conversation picks whether it runs on this PC or there, and the agent keeps working with your PC turned off. Run also works on the machine, and the server port reaches your localhost.

The nexora terminal command

Start conversations, send messages and see what needs you without leaving the terminal. With --json and the exit code, it works for scripts and for other agents. The commands are in Portuguese for now: iniciar starts, enviar sends.

Features

Built for running many sessions at once

With three or four agent conversations going at once, the hard part is knowing which one stopped to wait for you. Nexora solves that first.

Across all sessions

Live now

Every session on one board: needs you, working, ready and idle, with search. Allow, deny, answer the agent and commit without opening the conversation, with the PR status on every card.

See moreClose

Each session is a card in the column for its state. Whatever needs you sits at the top: permission requests, the agent's questions and plans to approve, all answered right on the card.

Space opens a quick view of the conversation, the arrow keys move from one session to the next and Esc closes it. Each card also shows the PR status and how many lines changed.

Rail and conversations

An icon rail that is always at hand, with conversations in a panel beside it that opens and closes with Ctrl+B without hiding the shortcuts.

See moreClose

The rail holds Live now, Conversations, Projects, Issues, Orchestrator, Scheduled, Usage and Resources, and it widens with each shortcut's name when you hover it. The conversations panel groups by project and branch, each showing what it is doing right now. Pages open in place instead of as tabs, so the tabs up top are just for conversations.

The session panel on the right starts closed and opens with one click. A bar at the bottom shows plan usage and Nexora's memory. F11 opens the big screen: full screen, everything larger and your sessions driven by the keyboard.

Orchestrator

Hand it a big task and it splits the work across sessions, each in its own worktree, then lets you know when it's ready for review.

See moreClose

For a task too big for a single session. The orchestrator breaks it into parts, starts an agent for each one in its own worktree, tracks them all on a canvas and tells you when there's something to review.

Scheduled prompts

Prompts that run on their own at a set time, like reviewing PRs every morning, each in a new session on the board.

See moreClose

Pick the project, the time, the days and the prompt. When the time comes, Nexora opens a new session with that prompt, and it shows up on the board like any other.

It works while Nexora is open. If it was closed at the scheduled time, the prompt runs when you open it, as long as it's the same day.

Multi-step flows

A template with several prompts in a row: the first goes right away and the rest wait for the agent to finish.

See moreClose

Split the steps with a "--- next step ---" line. When you send it, the first step goes to the agent and the rest wait in the queue, one at a time, as each turn ends.

Two come ready: from issue to PR (implement, test, review and open a draft PR) and review and test.

Big screen

F11 makes everything bigger, to use from across the room with just the keyboard: the session in focus up front and the others in rows.

See moreClose

The home view puts the session in focus up front and the others in rows: needs you, working, ready and idle. Enter opens, P and N allow or deny, 1 to 9 answer, Tab switches rows and F opens focus mode.

The top menu is always visible and pages open below it. The arrow keys move around any page, with a ring showing where the focus is.

Inside the conversation

Thinking in plain sight

Watch the agent think as the token count climbs, see what it's doing right now and which model answered each turn.

See moreClose

While the agent thinks, the conversation shows a live indicator with the token count going up, and afterwards how long it thought for.

At the bottom of the conversation you can see what it's doing right now (thinking, writing or running a command), with a running clock. Every turn ends with its duration and the model that answered, without dollar amounts.

Model and effort at hand

Model, effort, fast mode and Ultracode in a single menu. Your last pick carries over to new sessions.

See moreClose

The pill in the message box shows the model and effort in use. The menu lists the models your Claude Code offers, the effort levels, fast mode and Ultracode.

Your last choice applies to new sessions, and a reopened conversation comes back on the model and mode it had.

Message queue

Write your next message while the agent works. It waits in line and goes out as soon as the turn ends.

See moreClose

Got an idea while the agent is busy? Type it and send it. The message waits in a queue above the input and goes out when the turn ends, one at a time.

You can edit it, take it out of the queue or send it right away. If the turn stops on an error, the queue waits for you to decide.

Undo a turn

Every turn shows what changed in your files, and one click takes them back to before that message, without touching your commits.

See moreClose

Before each message you send, Nexora saves how your files looked, without touching your commits, branches or stash. Every turn shows how many files changed, with lines added and removed, and a button to see just that turn's diff in the Git panel.

Undo takes the files back to before that message. With Claude Code and Codex the conversation rewinds too; with other agents, Nexora warns you that the agent still remembers what it did. Files ignored by git stay as they are, and restore points are cleared after 14 days.

Session panel

Context usage, edited files, git, search and the session's PR beside the conversation. It tells you when it's time to compact and when the cache has expired.

See moreClose

Next to the conversation you get the session's environment (folder, branch, linked folders and MCPs), context usage by category and the files the session edited, each with its diff.

The Files, Git and Search tabs open the project tree, the changes and code search. When context passes 80%, the conversation offers /compact; when a session has sat idle long enough for the cache to expire, it warns you before everything gets re-read.

The PR tab shows the checks, failed ones first, the reviewers, review comments grouped by file and any conflict. You can merge, turn on auto-merge and get a request ready for the agent to fix a check or answer a comment.

Terminal and Run

A terminal in each session's folder, right below the conversation (Windows), and your project running on the right port for each worktree.

See moreClose

A PowerShell in the session's folder, below the conversation, that you toggle with Ctrl+`. It keeps running while hidden, and every session gets its own.

The Run button starts the project (dotnet, npm) on the right port for each worktree, so several copies of the same app can run side by side. The built-in terminal is Windows-only for now.

In your setup

Projects and worktrees

Your .code-workspace files become projects, with the main folder and the linked ones. Every session starts on the right branch and worktree, and you can switch the branch in the panel before you begin.

See moreClose

Nexora finds your .code-workspace files and git folders from VS Code, Cursor and Windsurf. A new task becomes a worktree with its own branch, off the project's base (dev, main…).

Each worktree gets its own port so it can run alongside the others, and the folder's branch can be switched in the session panel before you start.

GitHub

Your GitHub Projects issues as a kanban or a list, sessions started straight from an issue, and each session's PR watched: a failing check, a conflict or a new review lets you know or goes straight to the agent.

See moreClose

Your team's GitHub Project inside Nexora, with the same views. In kanban, drag an issue to another status; in the list, see assignees, labels, priority, size, PRs and iteration.

Open an issue to read the description, change its status and comment without leaving Nexora.

Two accounts work side by side, like your work and personal ones: each repository uses whichever gh account has access to it.

Every 2 minutes Nexora checks the PR of each open session. For a failed check, a conflict or a review comment, you choose in Settings: do nothing, just let you know, or ask the agent to fix it, with at most 3 automatic requests per PR each hour.

From issue to PR

  1. 1
    A worktree or a new sessionThe session starts in a fresh worktree off the project's base branch, like dev or main, after a fetch, or in a new conversation without a worktree, so you can pick the folder before sending.
  2. 2
    The issue goes into the promptThe issue link and its text, as bullet points, land in the draft of the first message, so the agent starts out knowing what to fix.
  3. 3
    The status moves on its ownThe issue moves to In progress when the session starts and to In review when the PR shows up.
  4. 4
    The PR on the boardCommit and open the PR from the session card, and the PR's checks, review and approval show up right on it.

Shared MCPs

The servers in .mcp.json start once per project and serve every session. They start when something needs them and shut down on their own.

See moreClose

With three sessions in the same project, each one would start its own copy of the servers in .mcp.json. In Nexora they run just once, in a hub the sessions share.

Each server starts on its first call and shuts itself down after 10 idle minutes. The browser is the exception: one per session, so no session messes with another's page.

VS Code conversations too

Sessions open in the VS Code extension show up on the board, and you can pick up any of them in Nexora without duplicating the conversation.

See moreClose

Sessions open in the VS Code extension appear on the board, each with its state.

When you reply to one of them from Nexora, the conversation continues in a copy with the full history, leaving the VS Code one untouched, and the list only shows the newest version.

Plan usage

How much of your 5-hour session and your week you have used, always in view in the bottom bar, with a heads-up near the limit and each project's share. No tokens spent.

See moreClose

The bar at the bottom of the window shows how much of the 5-hour session you have used, with the time until it resets, and how much of the week, read straight from Claude Code. The little bar turns orange near the limit and red when you're almost out. If you use Codex, its limits sit right beside.

The Usage page breaks the week down by project, without spending tokens.

Windows and Mac, always up to date

The same app on Windows 10 and 11 and on macOS, on Apple Silicon or Intel. When a new version is out, one click updates it, no website needed.

See moreClose

On Windows 10 and 11, an installer that doesn't ask for admin rights, or a portable version for PCs with stricter antivirus.

On Mac, builds for Apple Silicon and Intel, with the system's glass and ⌘ shortcuts. The built-in terminal and memory cleanup are still Windows-only.

When a new version comes out, an Update button appears at the top of the window. One click downloads it, closes Nexora, installs the update and opens it again.

Why Nexora

Why not just VS Code, or just the agent in a terminal?

Nexora doesn't replace your agent: its sessions are the same agent you already use, whether Claude Code, Codex, Gemini or another, with your account and your setup, such as CLAUDE.md, hooks, skills and MCPs. What changes is everything around it.

Instead of VS Code

For when you open VS Code just to talk to the agent and look at the code it changed.

  • Every session in view. In VS Code, each conversation lives in its own tab or panel. In Nexora, the board shows who needs you first.
  • Much lighter. About a tenth of VS Code's memory, in a single process.
  • One MCP hub per project. The servers in .mcp.json start once and serve every session, instead of one set per conversation.
  • Code within reach. File tree, editor, diffs of what changed, git and search, right next to the conversation.
  • One task, one worktree. New sessions start on the right branch and folder, off each project's base.

For breakpoint debugging or extensions, VS Code is still the place to be. Nexora opens the project there in one click.

Alongside your agents

For when you run several agent sessions at once, in the terminal or in the app.

  • Answer without hunting. Allow, deny and answer the agent's questions right on the card, with a system notification when a session is waiting.
  • Real projects. Your .code-workspace files become projects with linked folders, branches and worktrees.
  • Orchestrator. A big task split across sessions, each in its own worktree.
  • GitHub built in. Your team's issue board, PR status on each card and sessions that start from an issue.
  • Usage by project. How much of your plan each project used this week, read from /usage without spending tokens.

Conversations you started in the terminal or the extension show up on the board, and you can carry on with them in Nexora.

FAQ

Frequently asked questions

What exactly does Nexora do?

It's an app for working with several coding agent sessions at once, such as Claude Code, Codex and Gemini CLI, a kind of IDE built around them. It puts your conversations on a board that shows which ones need you, organizes projects and worktrees, brings in your GitHub issues and has an orchestrator that splits big tasks across sessions.

Who runs the builds and commands: Nexora or the agent?

The AI agent you already use, such as Claude Code, Codex or Gemini CLI. It's the one reading your code, editing files and running builds, tests and commands, on your account and your plan. Nexora has no AI of its own and doesn't run anything inside your conversations: it organizes your sessions, shows what Claude is doing and passes its permission requests to you, depending on the mode you pick. What Nexora does by itself is only what you ask for, like creating the worktree for a new task, running the project with the Run button or opening the built-in terminal.

Is it really free?

Yes. Nexora is free. The only thing you pay for is your agent's plan, from Claude or OpenAI, same as you do today.

Do I need a subscription?

You need the account of the agent you'll use: a Claude plan or an Anthropic key for Claude Code, a ChatGPT plan for Codex, a Google account for Gemini CLI and Antigravity, and so on. Nexora's sessions are your own agent, and the first launch helps you sign in to Claude Code if you haven't yet.

Is the app in English?

Yes. The whole app is in English and Brazilian Portuguese, and it follows your system language by default. To switch, open Themes, pick the language and reopen Nexora. The agent replies in whatever language you write in.

Does my code leave my computer?

Through Nexora, only if you tell it to. It doesn't send your code or your conversations anywhere and doesn't collect usage data. The exception is cloud machines, which are off by default: if you turn on Can go to the cloud for a project and pick the machine in a conversation, that project's code goes to the machine you connected. The agent talks to Anthropic or OpenAI as always, the same way it does in the terminal or in VS Code. Nexora itself only goes online to check for a new version, to talk to GitHub and to your cloud machine, if you connect them, and to download what you ask it to install on first launch.

What are cloud machines?

A way to take the load off your PC. The agent runs on a Linux machine of your own, over SSH, or on one Nexora creates on InstaBox or Freestyle with your API key. It is off by default, set per project, and each conversation picks where it runs. The agent keeps working with your PC turned off, and Bring it here brings the branch and the changes back to a worktree on this PC. The machine and its plan are yours, and Freestyle is still in testing.

Does Nexora see my password or token?

Sign-in is done by the agent itself, and Nexora only checks that it exists, without reading it. It only stores what you paste yourself: the cloud machine's API key, the claude setup-token token and the secrets an agent asks for through the form. All of it stays in the system vault, on this computer.

Can I use it alongside the VS Code extension?

Yes. Both use the same Claude Code, and conversations opened in the extension also show up on Nexora's board.

What happens to my projects' MCPs?

The stdio servers in .mcp.json start once per project and serve every session. Browser servers stay one per session, so sessions don't touch each other's tabs.

Windows says "Windows protected your PC" (SmartScreen). Is it safe?

The warning shows up because the installer doesn't have a digital signature yet (those are paid), and SmartScreen is wary of programs it hasn't seen before. It doesn't mean anything is wrong with the file. To install, click More info in the blue window, then Run anyway. If your browser blocks the download first, open the downloads list, click the three dots next to the file, choose Keep, and confirm with Keep anyway.

My Mac says Apple couldn't verify Nexora. How do I open it?

The app doesn't have Apple's paid signature (Developer ID), so macOS blocks the first launch. Drag Nexora from the DMG into Applications and try to open it once; when the message appears, dismiss it without moving the app to the Trash. Then go to System Settings › Privacy & Security, scroll down to Security, click Open Anyway next to the Nexora message and confirm with your password or Touch ID. After that it opens normally. On macOS 12 to 14 you can also Control-click Nexora, choose Open and confirm.

My antivirus blocked it. Now what?

Use the portable version: it runs on the .NET already installed on Windows, which usually gets past corporate antivirus software.

Does it work on Mac? What about Linux?

On Mac, yes: there are builds for Apple Silicon and Intel, on macOS 12 or later. 0.8 is Windows-only for now, and the Mac build is still 0.7.1. The built-in terminal and the memory release are also Windows-only. Linux isn't supported yet.

How do I update?

Nexora lets you know when a new version is out and shows an Update button at the top of the window. It downloads the update, closes, installs it and opens again.
